# Reel — 移动端视频应用（Vue 3 + Vite）

黑白主题的移动端视频应用：首页（推荐 / 最新 / 分类）、搜索、专题、播放页、短视频、直播、社区、同城、我的。

仓库里有四部分：

- **手机端**（`index.html` + `src/`）：给用户看的应用。
- **管理后台**（`admin.html` + `src/admin/`）：桌面端网页，管理视频、帖子、专题等，支持批量导入。
- **接口服务**（`server/`）：零依赖的 Node + SQLite 后端，同时托管打包好的前端和素材文件夹 `media/`。详见 [server/README.md](server/README.md)。
- **手机 App**（`mobile/`）：iOS / 安卓外壳，打开后加载服务器上的手机端网页。详见 [mobile/README.md](mobile/README.md)。

## 快速开始

```bash
npm install
node server/db/seed.mjs                      # 第一次：建库 + 示例数据
node server/create-admin.mjs admin 你的密码   # 第一次：建管理员
node server/index.mjs                        # 接口服务 http://localhost:3000
npm run dev                                  # 另开一个终端：前端开发服务（/api、/media 自动转发到 3000）
```

- 手机端：`http://localhost:5173/`（局域网内手机也能直接访问）
- 管理后台：`http://localhost:5173/admin.html`

部署时只需要一个进程：`npm run build` 打包到 `dist/`，再运行 `node server/index.mjs`，
手机端是 `http://服务器:3000/`，管理后台是 `http://服务器:3000/admin`。

## Docker 部署

仓库自带 `Dockerfile` 和 `docker-compose.yml`，把整个项目目录拷到服务器（NAS）上，在目录里运行：

```bash
docker compose up -d --build
```

- 访问 `http://服务器:27381/`（手机端）和 `http://服务器:27381/admin`（管理后台）。默认用冷门端口 27381，避免和服务器上别的服务抢 3000；要换端口用环境变量：`REEL_PORT=8088 docker compose up -d`。
- 数据都在目录里的两个文件夹：`data/`（数据库 `reel.db`）、`media/`（视频、封面）。重建镜像、升级都不会丢，备份这两个文件夹即可。
- 第一次启动时 `data/` 里没有数据库，会自动建库并写入示例数据。建管理员：

  ```bash
  docker compose exec reel node server/create-admin.mjs 登录名 密码
  ```

- 容器以 uid 1000 运行，`data/`、`media/` 要让 uid 1000 可写（NAS 上一般就是第一个用户），否则用 `chown -R 1000:1000 data media`。
- 更新代码：在本机运行部署脚本，它会上传代码、先备份数据库、再重建容器并等到健康检查通过（不会碰服务器上的 `data/` 和 `media/`）：

  ```bash
  DEPLOY_HOST=root@服务器 DEPLOY_DIR=/服务器上的/reel 目录 bash scripts/deploy.sh
  ```

  需要能用 SSH 密钥免密登录服务器。也可以手动把代码拷过去覆盖，再 `docker compose up -d --build`。
- 数据库备份：每次用脚本部署前自动备份到 `data/backups/`（默认保留最近 10 份）；随时手动备份：`docker compose exec reel node server/backup-db.mjs /data/backups`。恢复时停掉容器，把备份文件改名覆盖 `data/reel.db` 再启动。
- 国内拉 npm 依赖慢时：`NPM_REGISTRY=https://registry.npmmirror.com docker compose build`。
- 没有 HTTPS，`/media/` 下的文件也不需要登录就能访问，适合内网使用；要放到公网，请在前面加一层带 HTTPS 的反向代理。

需要 Node.js 20.19+ 或 22.12+（推荐 22 LTS，见 `.nvmrc`）。

打包产物兼容 iOS 14+ 的 Safari / WKWebView、Android System WebView（Chrome）87+。

## 技术栈

| | |
|---|---|
| 框架 | Vue 3（`<script setup>` 单文件组件） |
| 构建 | Vite |
| 路由 | Vue Router（hash 模式，任何静态服务器 / App WebView 都能直接用） |
| 状态 | Pinia |
| 样式 | 原生 CSS + CSS 变量（设计令牌），组件内 scoped 样式 |

没有引入任何 UI 组件库，图标是内置的 SVG，体积很小。

## 性能设计

- **按页面拆包**：首页随入口加载，其余每个页面单独一个 JS 文件，空闲时预取，之后切换无等待。框架（`vendor`）、数据层（`data`）、公共组件（`common`）各自独立成包，可长期缓存。
- **缓存与压缩**（接口服务托管 `dist/` 时）：`assets/` 下带 hash 的文件缓存一年（`immutable`），第二次打开不再下载；`index.html`、`admin.html` 每次向服务器确认（`no-cache` + `ETag`，没变回 304），重新部署后马上用上新版本。接口 JSON 和 HTML / JS / CSS / SVG 按 `Accept-Encoding` 压缩（br 优先，其次 gzip），20 条视频的列表 235 KB → 约 26 KB。
- **主 Tab 常驻**：底部 6 个主页面切换时不销毁（KeepAlive），保留滚动位置和状态，切回来是瞬间的；首页每个分类 Tab 也各自保留状态。
- **图片懒加载**：封面用原生 `loading="lazy"` + 异步解码，只加载屏幕附近的图；加载前先显示生成的占位图，加载失败也不会破图。
- **后台不耗电**：短视频页切到其他 Tab 时自动暂停计时和动画。

| `#/short` | 短视频（推荐流，见下面「短视频」） |
| `#/live` | 直播 |
| `#/community` | 社区：最新 / 热门 / 关注 / 收藏四个标签各自分页、各记各的滚动位置；关注 / 收藏要登录；再点一次底部「社区」先回顶部、在顶部再点刷新；搜索框搜帖子 |
| `#/nearby` | 同城 |
| `#/me` | 我的 |
| `#/search?q=&type=post` | 搜索：没有关键词时是建议页（近期搜索的关键词：登录后存服务端、未登录存本机，可逐个删除 / 全部清除；热门搜索只列搜得到东西的词）；有关键词时「视频 / 帖子」两个标签同时搜、滚到底自动加载。从建议页搜索多一条历史，返回回到建议页；结果页里再换词、切标签不多历史；点进视频 / 帖子再返回时结果和滚动位置原样恢复 |

| `#/post/:id` | 帖子详情（点社区卡片进来；作者栏可关注，取消关注先确认；关联视频紧跟标题（帖子主图和视频封面不是同一张时，视频块左右拼成两半、播放键压在中缝上），正文里的网址 / 电话 / 邮箱可以点，配图点开全屏看大图（左右滑、双指 / 双击放大），话题点了搜相关帖子；底部阅读数 / 分享 / 收藏；返回到这一篇时原位恢复，同一次打开 App 每篇只记一次阅读；「下一篇」替换当前记录，返回键直接回到进来之前的页面） |
| `#/creator/:id?tab=videos\|posts\|media` | 创作者主页（社区卡片 / 帖子详情的头像和名字、搜索页的热门创作者点进来）：头图、头像、关注、粉丝 / 视频 / 帖子数，下面「视频 / 帖子 / 媒体」三个吸顶标签，视频可按最新 / 最热排；「媒体」是他发过的所有图（视频封面 + 帖子的图）拼成的三列照片墙，点图片全屏看大图（从那一格放大出来、关掉缩回去，左右滑看已加载的图），点视频进播放页；三个列表都滚到底自动加载；标签记在地址栏，点进视频 / 帖子再返回时列表和滚动位置原样恢复 |
| `#/video/:id?list=topic:<id>&i=<n>&sort=<n>` | 播放页（视频卡片点进来就是它；数据库 `videos.playback_url` 有地址时播放真实视频，没有时如实显示封面和「暂无视频源」；从专题点进来时带上 `list` / `i`，播完接着播专题的下一条，见下面「播放页」） |
| `#/history` | 观看历史（每条有进度条和「看到 12:34 / 已看完」，点进去接着看；× 删一条，几秒内可撤销；右上角「清空」先确认） |
| `#/favorites?tab=video\|post\|topic` | 我的收藏：视频 / 帖子 / 专题三个标签，卡片上直接取消收藏（变暗留在原处，再点可收藏回来） |
| `#/follows` | 我的关注：点进创作者主页；「已关注」先确认再取消 |
| `#/library` | 片库 |

不认识的地址会自动回到首页。返回键的规则（和抖音、B 站一样）：

- 在「短视频 / 直播 / 社区 / 同城 / 我的」上按返回先回到首页，在首页再按一次才离开 App。从首页切到别的 Tab 时压栈，非首页 Tab 之间切换和首页顶部分类切换时**替换**历史记录，返回键不会在 Tab 之间来回跳；直接打开（书签、分享链接、刷新）非首页 Tab 时，也会在它下面垫一条首页记录（只改历史，不会先显示一下首页）。
- 进入搜索、专题等子页面时正常压栈，返回键回到上一页。
- 弹层（底部弹层、登录框等）开着时，返回键 / 返回手势只关弹层，页面不动；换页面时弹层自动关掉，不会留到下一个页面上。新写的弹层用 `src/composables/useBackDismiss.js` 接入（`BottomSheet` 已经接好）。

新增底部导航页面时，在 `src/config/nav.js` 的 `MAIN_TABS` 里登记它的组件名（`view`），它才会常驻；漏登记时开发环境会在控制台提示。

## 播放页

- **没有片源**：只显示封面和「暂无视频源 · 时长」，没有进度条、播放键、全屏这些控件，不计播放、不进观看记录；「看相似推荐」滚到下面的相似推荐。
- **续播**：看到哪儿记在本机（最多 50 条），登录后服务端也记（切后台、关页面时也会上报）；打开时取两边更新的那一份，从那里接着播并提示「已从 x:xx 继续播放」，可一键「从头播放」。快看完（剩 5 秒内）的下次从头播。
- **播完**：显示「重播 / 下一个」，开着「自动连播」（播放设置里，和短视频共用）时 5 秒倒计时后自动播，可取消。下一个是来源列表的下一条（专题里点进来的），没有就是相似推荐的第一条；跳过去替换当前记录，返回键直接回到进来之前的页面。
- **全屏**：正在播放时手机横过来自动全屏，竖回来退出；浏览器不支持元素全屏（如 iPhone）时用页面内铺满屏幕的「伪全屏」，返回键先退出它。
- **倍速**：不是 1.0x 时控制栏上直接显示当前倍速（倍速记在本机，短视频也用同一个）。
- 信息区有作者（点进主页、关注）、可展开的简介、热门榜名次、所属专题；没登录时点赞 / 收藏 / 关注会先登录，登录后先取回自己原本的状态，再补做这一下。

## 短视频

- **推荐流**：从全部已上架视频里推荐，后台「加入短视频」的优先；每次打开 App、或者已经在短视频页时再点一次底部的「短视频」，都会换一批并回到第一条；切到别的 Tab 再回来不会变。一直往下刷不会到底（整个视频库刷完会重新洗牌接着给）。最近刷到过的 100 条记在本机，下次打开时排到后面；登录后最近看过的也会往后排。
- **进度条**：点一下跳过去；按住横着拖时屏幕中间显示「当前 / 总时长」，松手才跳，拖的时候不会翻页（从进度条上往上滑照常翻页，不跳进度）。键盘聚焦后左右方向键 ±5 秒。
- **长按快进**：按住屏幕左右两侧边缘（各约 1/5 宽）2 倍速播放，顶部显示「2X 快进中」，松手恢复原来的倍速（不改播放设置）。点一下仍是播放 / 暂停，从边缘上下滑照样翻页。
- **作者**：点左下角的名字或右侧头像进创作者主页。
- **点按**：单击稍等一下（约 0.25 秒）才暂停 / 播放，双击点赞（手指处冒出点赞图标，没登录先登录、登录后补上）；标题超过两行点一下展开；#话题点了去搜索；有片源且 1 分钟以上的条目有「看完整版」进播放页。
- **不喜欢**：少推这类视频并自动划到下一条（登录后记在服务端，未登录记在本机）。
- **没有片源的条目**：只显示清晰的封面和「暂无视频源 · 看详情」，大约 15 秒后自动划到下一条；不显示恢复声音、全屏、小窗。
- **全屏 / 小窗**：左上角两个按钮，只在有片源的条目上出现。
- **刷新**：在第一条往下拉，或者再点一次底部「短视频」，换一批推荐；翻页失败时最后一格显示「点击重试」，网络恢复后自动接着加载。
- **本机记住**：声音开关、倍速、自动连播 / 循环播放都记在本机（`reel:prefs`），下次打开照旧。

## 数据与接口

所有页面只通过 `src/api/index.js` 取数据，它请求 `server/` 提供的接口（说明见 `src/api/README.md`）：

- **线上只用真实接口**：打包（`npm run build`、Docker）由 `.env.production` / Dockerfile 固定 `VITE_API_MODE=http`，接口连不上时页面显示「加载失败 + 重试」，永远不会悄悄换成演示数据。
- 本地开发默认 `auto`：每次读取都先请求接口，只有某次**列表**读取连不上（断网、超时、5xx）时，这一次用演示数据并提示「接口未连接，当前展示演示数据」；下一次请求成功（或浏览器报告网络恢复）就提示「已重新连接」，之后照常用接口。读取某个具体的视频 / 帖子、「我的」相关数据、所有写操作都不会退回演示数据。
- 演示数据的 id 都是 `demo:` 开头的字符串，不会和真实 id 撞上；对演示内容点赞、收藏、关注不发请求，直接报错「演示内容，无法操作」，页面照常回滚并提示。
- `.env.local` 里写 `VITE_API_MODE=http` 只用接口，写 `mock` 只用演示数据（详见 `src/api/README.md`）。
- 图片统一用 `{ src, fallback }` 结构：`src` 是图片地址，`fallback` 是加载前 / 加载失败时显示的占位图。
- 视频、封面上传到 `media/` 后地址是 `/media/...` 这样的站内路径，所以手机端要和接口服务同源访问（Node 直接托管 `dist/`，或者开发时走 Vite 转发）。

## 登录与账号

后端自带鉴权（`server/README.md` 有完整说明）：

```bash
node server/create-admin.mjs admin 你的密码
```

- 未登录也能正常浏览，只有点赞、收藏、关注、观看历史需要登录 —— 点这些按钮会弹出登录框，不会跳走页面；登录成功后自动补做刚才那一下（点赞、收藏……），从「我的」点观看历史 / 我的收藏 / 我的关注登录的，登录后直接进入那一页。「我的」里的退出登录要先确认。页面里用 `auth.requireLogin(地址, { then })` 接入（见 `src/stores/auth.js`）。
- 登录状态存在 `localStorage`，刷新和关掉重开都还在。
- 管理员在「我的 → 账号管理」或管理后台的「账号」页里建账号、重置密码、停用账号。

## 管理后台

用管理员账号登录 `admin.html`（手机端「我的 → 管理后台」也能打开）。桌面浏览器使用，1280 宽以上效果最好。

| 页面 | 能做什么 |
|---|---|
| 概览 | 各类数据总数、待完善的数据（缺播放地址 / 封面 / 时长）、最近添加的内容 |
| 视频 / 帖子 / 专题 / 创作者 / 搜索热词 | 搜索筛选、分页排序、新建编辑、批量上架下架 / 改专题 / 加标签 / 删除、导出 CSV |
| 首页推荐 | 编排首页「推荐」的分区和每一批（换一批）的视频，可按专题 / 最热 / 最新自动生成 |
| 素材文件 | 浏览 `media/` 文件夹、拖拽批量上传、复制地址、预览；「扫描导入视频」把文件夹里的视频一次建成视频记录，并在浏览器里自动读取时长、截取封面 |
| 批量导入 | 上传 CSV / Excel（.xlsx）/ JSON，或直接粘贴 Excel 里复制的单元格；自动对应列名，预检后再导入，重复数据可跳过或更新，错误行可下载报告 |
| 账号 | 建账号、重置密码、停用、设管理员 |

常用做法：

- **批量加视频文件**：把视频放进 `media/videos/`（或在「素材文件」里拖进去上传）→「扫描导入视频」→ 勾选、统一设置专题和分类 → 导入。
- **用表格批量改数据**：在列表页「导出」→ 用 Excel 改 → 在「批量导入」里选「更新已有」导回去。导出的表头就是导入模板的表头，不用手动对应。
- 每种数据都可以在「批量导入」里下载模板；中文 Excel 默认保存的 GBK 编码 CSV 也能直接导入。

## 主题与配色

设计令牌在 `src/styles/tokens.css`：

- `--accent`：强调色（当前白色）。换成别的颜色就是彩色主题。
- `--t2` 等：中性灰文字色。
- `--media`：照片滤镜。默认 `none`（照片保留原色），改成 `grayscale(1)` 就是照片也全黑白。

## 动效

全 App 一套动效语言：手指碰到的地方有弹性，大面积的面顺滑连续，东西从哪来、到哪去看得出来。令牌和规则在 `src/styles/motion.css`（开头有完整说明），JS 里用 `src/utils/motion.js`。

- **原则**：只动 `transform` / `opacity`；按下的那一帧就有反馈；入场不超过约 450ms；随时可以打断、打断后停在正确状态；转场期间照样能点（离开中的东西不接手指）；只用黑白灰。系统开了「减少动态效果」时全部收敛成几乎不动，状态照样切换。
- **弹簧**：三根真实的阻尼弹簧，用 CSS `linear()` 描出来（`@supports` 里），老浏览器（iOS 17.2 / Chrome 113 以前）退回拟合出来的 `cubic-bezier`。每根弹簧要配自己的时长：

  | 令牌 | 用在 | 参数（质量 1） | 停稳 |
  |---|---|---|---|
  | `--spring-snappy` + `--dur-spring-snappy` | 手指碰到的反馈：按压松手、开关、指示条、提示条出现 | stiffness 700 / damping 38，过冲约 4% | 283ms |
  | `--spring-smooth` + `--dur-spring-smooth` | 大面积的面：底部弹层、Tab 内容滑入、被顶开的提示条 | 400 / 38，几乎不过冲 | 358ms |
  | `--spring-bouncy` + `--dur-spring-bouncy` | 小的「庆祝」元素：点赞、选中的图标、角标 | 600 / 26，过冲约 14% | 382ms |

  JS：`el.animate(frames, spring('snappy'))`；松手接着手指速度走用 `springFrom('smooth', 速度)`。旧的 `--ease-spring` 现在就是 bouncy 的形状。其余曲线：`--ease-out`（进场）、`--ease-in`（离场）、`--ease-fluid`（iOS 式流体减速，页面推入 / 返回）。
- **页面切换**（`components/motion/pageTransition.js` + `App.vue`）：进子页面新页从右边沿流体曲线滑入（440ms），上一页往左让出 30% 并变暗；返回反过来（380ms）；底部 Tab 之间新页从切换方向滑进 20px 并淡入，旧页原样垫在下面。刚打开、减少动态效果、iOS 边缘右滑返回（浏览器自己滑过）时不做动画。
- **共享元素过渡**（`components/motion/hero.js`）：点视频卡片，封面从卡片飞进播放器（smooth 弹簧，合成线程跑），落地露出播放器、这时才开播（飞行中只缓冲，不会先出声、开头也不会在看不见的时候播掉）；返回时播放器（带着此刻的画面）缩回原来那张卡片；播放页里点相似推荐，缩略图飞进播放器。飞行中再返回 / 再点会掉头，跳转失败会飞回卡片。减少动态效果、全屏 / 小窗、窗口变了、看不到卡片时走普通转场。
- **底部导航**（`components/tabbar/tabMotion.js`）：按下图标沉到 .88、光点朝手指那格探一下；松手 bouncy 弹起、实心图标从中心长出来，光点用 smooth 弹簧滑过去（拉成一道细光痕再收回一粒，和 Tab 内容滑入同一根弹簧），其余几格轻轻暗一下；再点当前 Tab 图标轻跳 + 光点呼吸（照常回顶 / 刷新）；手指划出这一格就取消。先建好动画、下一帧再切页面，切页面时导航栏不卡。
- **共享元素过渡（hero）契约**：跳转前调 `overrideNextTransition('pg-hero' | 'pg-hero-back')`，下一次完成的跳转就用它（跳转失败或 1.5 秒内没跳就作废；减少动态效果、浏览器自己滑过时照常规则）；跳转完成后看 `pageMotion.name` 确认实际用上了没有。飞行中的元素放在 `Z.hero`（45）层。样式见 motion.css「共享元素过渡」。
- **层级**（`--z-*` / `Z`）：底部导航 30 → 转场中盖在上面的页面 40 → hero 浮层 45 → 播放器伪全屏 50 → 弹层遮罩 / 弹层 60 / 61 → 看大图 70 → 提示条 80。
- **面**：底部弹层（含登录框）用 smooth 弹簧升起 / 收起，下拉松手接着手指的速度走（甩下去、或弹回时先顺势再回来），升起或弹回途中也能直接抓住；提示条从下面弹上来，新的一条把旧的往上顶开一格；按压松手卡片用 snappy、小图标用 bouncy；返回键顶栏和首页分类栏在内容滚过去时底边细线变亮、下面多一道淡阴影（IntersectionObserver 哨兵，不挂滚动监听，`components/motion/scrollEdge.js`）。
- **JS 里读时长令牌**：一律用 `cssDuration()` / `parseMs()`（`utils/motion.js`）。打包时 CSS 压缩会把 `120ms` 改写成 `.12s`，直接 `parseFloat` 会读成 0.12 毫秒，动画在线上一闪而过（开发环境看不出来）。

## 无障碍与交互细节

- 所有按钮、链接、卡片都能用键盘 Tab 聚焦，回车 / 空格触发，键盘聚焦时显示白色焦点框（鼠标和触屏不显示）。
- 底部弹层打开时焦点移入，Esc 可关闭，关闭后焦点回到原来的按钮。
- 小图标按钮扩大了可点击区域，视觉上不变。
- 分享在手机上调用系统分享面板，其他环境复制链接。

## 打包成 iOS / 安卓 App

App 工程在 `mobile/`（Capacitor 8，自己的 `package.json`，详见 [mobile/README.md](mobile/README.md)）。用的是**外壳模式**：App 里只有一个启动页，连上服务器后加载服务器上的网页版，所以**服务器部署后 App 自动是最新的**，不用重新安装；只有启动页、图标、原生代码、版本号变了才要重新打包。

- 安卓：本机 `cd mobile && npm ci && npm run android:release`，得到签名好的 APK；改名成 `reel.apk`，在管理后台「素材文件」的 `app` 文件夹里上传（已有旧的先删掉，后台上传不覆盖同名文件），安卓浏览器里「我的」就会出现「下载安卓 App」。签名钥匙在仓库外（`~/.reel-keys/`），**务必备份**，丢了就没法给已安装的 App 发更新。
- 服务器要先部署这一版：`.apk` 上传、「下载安卓 App」和 App 里的「我的 → 切换服务器」都在这一版的服务器 / 网页版里。
- iOS：在 GitHub Actions 的 macOS 机器上打包（`.github/workflows/mobile-ios.yml`，需要 Apple 开发者账号）。证书、描述文件存在仓库的 GitHub secrets 里，打出 Ad Hoc 安装包（保留 3 天）或上传 TestFlight；没配签名时只编译模拟器版本、跑模拟器冒烟测试。一步步的做法见 [mobile/README.md](mobile/README.md)「iOS」。
- `.github/workflows/mobile-android.yml` 是安卓的 CI 备份，只编译调试版 APK；正式的安卓包只在本机签名打包，发布钥匙不进 GitHub。
- 默认服务器地址：本机打包写在 `mobile/.env.local`（`REEL_SERVER=http://内网地址:27381`，不入库），GitHub Actions 里用 secret `REEL_SERVER`；App 里「我的 → 切换服务器」可以随时改，以后换成 HTTPS 域名也一样。
- 网页版靠 User-Agent 里的 `ReelApp/<版本>` 认出自己在 App 里（`src/utils/shell.js`）。
